# 快速学习笔记规则

目标：让读者快速抓住主线，能用自己的话解释原因，并在具体场景中做判断。
默认读者是有大学基础、尚无行业经验的应届生。用平等、直接的大白话，
专业概念要讲准；保留读懂所需的前提、因果和条件。

## 动笔前

- 完整读取转写和元信息，选出本次最值得学会的一条主线，以及支撑它的
  核心问题。问题按理解所需的先后排列，可以调整视频顺序。
- 优先选用视频里的一个具体例子贯穿讲解，减少读者反复熟悉新背景的负担。
- 区分作者观点、案例做法和普遍结论。口述有矛盾、关键步骤缺失或术语
  存疑时，明确写出“视频未讲清／待核实”，不自行拼出确定答案。
- 教学补充须标“注：”。补充类比、情境题只用于帮助理解已有论点；
  不补造指标、阈值、命令、产品行为或实现细节。

## 成稿顺序

### 1. 这次要弄懂什么

标题下用一行保留来源、作者、时长和链接，再用一句话说明学完能解决
什么具体问题。接着列出核心问题，通常 3–5 个；内容简单时少列，长课可
按独立主题分组，不凑数量。

问题要有具体情境，能让读者先猜、比较或解释原因。例如“两个 Agent 都
订好了票，为什么还不能说它们一样好？”比“Agent 评估指标有哪些？”
更能引出学习动机。提示读者先试答首题，带着没答出的地方往下读。

### 2. 沿着问题讲明白

正文小节标题与开篇问题对应。每节围绕一个问题，用短段落完成：

- 先用一句大白话回答，再解释“为什么”，保留必要的因果关系。
- 用一个小例子把解释落到具体情境。优先复用贯穿全文的原视频案例。
- 确有易错点时，补一句“容易混淆在哪里／什么条件下不适用”。

以上是思考顺序，不必在每节重复“结论、原理、案例”等栏目。首次出现
的必要术语就地解释，中文为主，英文名只在有助于查资料时附上；需要的
前置知识用一两句话补齐，不把术语表放在开头。

将至少一张简洁的 mermaid 图放在最需要理解关系的地方。图用于解释流程、
因果、判断分支或交互，节点用短中文；避免把正文要点再画成一棵目录树。
交互式思维导图另按 SKILL.md 第 6 步生成，用于回顾问题与回答骨架。

how-to 内容在相关问题下给出原视频支持的最少步骤和成功表现；命令、
配置仅在转写明确提供时保留，不为“可操作”而补造。进阶细节按需后置，
不打断初次学习的主线。

### 3. 合上笔记，讲给同学听

给出一个具体的费曼复述任务：请读者不用原文、用 30–60 秒向没学过这段
内容的同学解释一个核心问题。提示可围绕“解决什么问题 → 为什么这样
做 → 举个例子”，不要先给一段可直接背诵的完整示范回答。

列出 2–3 个内容检查点，并说明漏了某一点应回看哪个问题。例如“只说出
结果、过程、成本三个词，还需要讲清：为什么任务成功仍可能做得不好”。
以读者能否解释原因和例子为检查依据。卡住时，回看对应小节，改写成自己的
一句话，再合上笔记讲一次；不能因笔记已经生成就说读者学会了。

### 4. 换个场景试一题

给一道短情境题，检验读者能否把刚学到的原因或方法用到另一个场景。
要求做判断、解释原因或选下一步，避免只考术语默写；所需知识限于正文。
题目可以是整理者设计的，标“注：练习情境为学习用例”。

若视频确有可直接练习的操作，可用一个最小实践任务替代情境题，写清
输入、要做的动作和如何判断结果；无需再附一串泛泛的行动项。

### 5. 参考答案与回看位置

把情境题的参考判断、理由和回看位置统一放在全文末尾，让读者先尝试。
实践任务则给出预期现象与自查依据。指出常见误判为什么站不住脚；
涉及视频未解答的开放问题时说明局限，不给唯一结论。

只在确实影响理解时，另留少量待查问题。转写质量说明、类型打分等交付
信息放在回复中；必要的内容疑点就地说明。

## 简短而不晦涩

- 普通短讲解优先写成约 600–1000 字的笔记，长课按独立主题和复杂度增减。
  不为字数删掉关键原因、例子、边界，也不为覆盖所有原句而扩写。
- 一句话推进一个意思；同一知识点只在最合适的位置讲清。复述题用于
  检查，不再重抄一遍正文。
- 将“轨迹效率”解释为“完成任务有没有绕远路”，但保留必要术语，方便
  读者以后识别它。避免用一串新术语解释另一个术语。
- 删除夸张口播、面试恐吓、口号、客套和空泛的“掌握／深入理解”。
  保留能解释原因、帮助判断或防止误用的内容。
- 给读者留主动思考的机会，同时提供简短反馈。引导语点到为止，不写成
  冗长的师生对话，也不要求用户先回答才能交付笔记。

## 写法示例（仅展示一个小节）

依据：[Agent 性能评估视频，第 9 集](https://www.bilibili.com/video/BV1aQMX6oEni/?p=9)。

### 两个 Agent 都订好了票，为什么还不能说它们一样好？

订到票只说明任务成功了。一个 Agent 用三步完成，另一个绕了五十步，
调用了很多无用接口；结果一样，过程却有差别。

所以要一起看三件事：事情办成了吗，过程中有没有走弯路，花了多少时间
和费用。“轨迹效率”说的就是完成任务有没有绕远路。

合上笔记试着讲：为什么“成功率相同”还不足以比较两个 Agent？请举出
一个视频里的例子。

## 交付前自检

- 开篇问题是否对应正文，读者是否知道为什么值得学？
- 每个核心问题是否讲清原因，并有例子帮助理解？必要术语是否就地解释？
- 复述任务是否要求自己组织语言，检查点是否能帮助找到具体卡点？
- 情境题是否需要运用正文，答案是否后置并解释理由？
- 视频观点的条件、疑点和教学补充是否分清？是否删掉重复与夸张措辞？
